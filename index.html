本次项目总结

以下是我对自己这次学习过程的回顾

本次项目中，我向 WorkBuddy 请教网站搭建方法，同时上网检索各类 Agent 工具的下载与使用方式， 循序渐进地接触、学习这些陌生技术领域。我深刻体会到，Agent 工具能为日常学习提供有力支持， 在编程练习、习题解析、项目搭建等场景发挥重要作用。

我是怎么做的

整个过程可以拆成三个步骤，每个步骤都有截图记录

1

先在 GitHub 建一个仓库，把图片放进去

我一开始连 GitHub 是什么都不知道。在豆包的指引下，我逐项确认了仓库名称、描述和可见度， 特别是“必须设为 Public 才能开网页”这一点，如果漏掉后面就发布不出去。 建好之后，我把三张过程截图上传到了仓库里。

2

打开 Trae 的 Agent，让它帮我生成网页

这是我第一次理解“Agent 需要一个工作目录”这件事。 界面上“打开文件夹 / 新建项目 / 克隆 Git 仓库”几个入口，说明它不是单纯聊天， 而是要真的进到我的文件里动手干活。把图片链接和文字说明交给它，它就能生成一个完整的网页文件。

3

最后在 WorkBuddy 里逐项检查，再上传发布

拿到生成的网页后，我并没有直接交上去。WorkBuddy 主动列出了三个待办： 截图还没放进去、署名要换成本人、示例内容需要改成真实经历。 这让我意识到，AI 交付的东西不等于可以直接用的东西，人工核对这一步省不掉。 改完之后再上传到仓库，开启 GitHub Pages，网站就上线了。

一点体会

这次做下来，我最大的感受是：Agent 不是“一键生成”的魔法。 它确实能在我完全不懂 HTML 的情况下，帮我搭出一个能看的网站，但它不知道我要什么， 也不知道哪些内容不能瞎编。仓库名要我自己起，图片要我自己截，截图放在哪一段、 配什么说明，这些都得我来判断。

另一个体会是，真正难的不是“让它做”，而是“判断它做得对不对”。 第一次看到生成的网页时，我觉得挺好的；仔细一看才发现署名还是模板里的名字， 截图根本没显示出来。如果不检查就交，这些都会被老师看到。

所以对我来说，Agent 更像一个执行力很强、但需要明确指令和事后验收的助手。 把它用在编程练习、习题解析、项目搭建这些场景，确实能省下大量查资料和试错的时间， 但前提是我得知道自己在做什么、要什么、以及怎么判断结果对不对。
